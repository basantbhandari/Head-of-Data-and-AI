# Engineering terms with their definitions

One-line definitions of common data engineering terms.

- **ETL** – Extract, transform, and load it into a target system.
- **ELT** – Load data first, then transform it inside the warehouse or lake.
- **Data Warehouse** – Structured storage optimized for analytics and reporting.
- **Data Lake** – Stores raw, unstructured, or semi-structured data at scale.
- **Data Lakehouse** – Combines data lake flexibility with warehouse performance.
- **Data Pipeline** – Automated flow that moves data between systems.
- **Batch Processing** – Processes large data chunks at scheduled intervals.
- **Stream Processing** – Processes data continuously as it arrives.
- **Real-Time Processing** – Instant processing and response to incoming data.
- **Data Modeling** – Designing how data is structured and related.
- **Schema** – Defined structure of fields, types, and constraints.
- **Star Schema** – Simple model with a central fact table and dimensions.
- **Snowflake Schema** – A normalized version of the star schema with more tables.
- **OLTP** – Systems for fast, real-time transactional workloads.
- **OLAP** – Systems for analytics, aggregations, and insights.
- **Distributed Systems** – Multiple machines working together as one system.
- **Message Queue** – Stores messages to enable asynchronous communication.
- **Data Partitioning** – Splits data into segments for faster processing.
- **Data Sharding** – Distributes data across servers for scalability.
- **Indexing** – Creates fast lookup structures for quicker queries.
- **Caching** – Stores frequently used data for faster access.
- **Data Governance** – Policies to ensure data security and consistency.
- **Data Quality** – Ensures data is accurate, consistent, and reliable.
- **Data Lineage** – Tracks data's journey from source to destination.
- **Data Catalog** – Inventory that helps users find and understand data.
- **Orchestration** – Coordinates and manages multi-step data workflows.
- **Workflow Scheduler** – Triggers tasks or pipelines at set times or events.
- **Fault Tolerance** – System continues running even if parts fail.
- **Elasticity** – Automatically scales resources based on demand.
- **Scalability** - Handles growing workload by adding more resources.
- **Fact Table -** Stores measurable numeric data from transactions or events.
- **Dimension Table -** Stores descriptive attributes that give context to fact data.
- **Data Mart** - A subset of a data warehouse focused on a specific business area or department.
- **Idempotency** - A property where running the same operation multiple times produces the same result without side effects.
- **Data Deduplication** - The process of removing duplicate records to ensure data accuracy.
- **Data Normalization** - Organizing data to reduce redundancy by splitting it into related tables.
- **Data Denormalization** - Combining tables to reduce joins and improve read performance.
- **CDC (Change Data Capture)** - Tracks and captures changes in source data to sync with target systems.
- **Data Replication** - Copying data across multiple systems or locations for availability and reliability.
- **Data Ingestion** - The process of collecting and importing data from various sources into a system.
- **Data Wrangling** - Cleaning and transforming raw data into a usable format.
- **Data Skew** - An uneven distribution of data across partitions that causes processing bottlenecks.
- **Backpressure** - A mechanism to handle situations when data is produced faster than it can be consumed.
- **Data Retention Policy** - Rules defining how long data is stored before deletion or archiving.
- **Data Masking** - Hiding sensitive data by replacing it with fictional but realistic values.
- **Data Encryption** - Converting data into a coded format to prevent unauthorized access.
- **Schema Evolution** - The ability to modify a data schema over time without breaking existing systems.
- **Schema-on-Read** - Applying schema to data only when it's read, common in data lakes.
- **Schema-on-Write** - Applying schema to data before it's written, common in data warehouses.
- **Data Observability** - Monitoring data pipelines to detect issues like errors, delays, or anomalies.
- **Data Contract** - An agreement defining the structure and expectations of data exchanged between systems.
- **Idempotent Pipeline** - A pipeline designed to produce the same output even if re-run multiple times.
- **Late-Arriving Data** - Data that arrives after its expected processing window.
- **Data Freshness** - A measure of how up-to-date data is relative to real-world events.
- **Reverse ETL** - Moving data from a warehouse back into operational systems like CRMs.
- **Data Mesh** - A decentralized approach where domain teams own and manage their own data.
- **Feature Store** - A centralized repository for storing and serving machine learning features.
- **Watermarking** - A technique in stream processing to handle late data within a time threshold.
- **Data Compaction** - Merging small files into larger ones to improve storage and query efficiency.
- **Columnar Storage** - Storing data by columns instead of rows for faster analytical queries.
- **Row-Based Storage** - Storing data by rows, optimized for transactional workloads.
- **Data Skew Handling** - Techniques to balance uneven data distribution during processing.
